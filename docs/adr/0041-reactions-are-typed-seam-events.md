# Reactions are typed seam events — admissible agreement evidence, never a tap

**A reaction crosses the wall like any message — and today it crosses mutilated.** whatsmeow has no separate reaction event: a 👍 arrives as an ordinary `*events.Message` whose `ReactionMessage` is set, and the capture guard's scope test is per-chat, never per-message-kind, so an in-scope reaction already writes a `wa_events` row — `event_type='message'`, empty text, no target pointer. The husk is then treated as a message downstream: embedded, batched into the chat's turn, indistinguishable from someone saying nothing. What never crossed is the signal — the emoji and the message it points at. The decision: the signal crosses, **both directions** (a rep's 👍 on the customer's request and a customer's 👍 on the rep's quote are both agreement), under the unchanged capture guard and ADR-0033's provenance rule. A reaction is evidence in a conversation, exactly like text.

**Its seam shape is a new `event_type: 'reaction'`; the payload stays `v:1`** with a reaction-specific shape: the reaction's own stanza id, chat, sender, `from_me`, the target message id read off `ReactionMessage.Key`, the emoji, push-name where present, and the backfill marker. Not an additive field on `'message'`, although that is the established cheap path (`push_name`, `backfill`), because a reaction is not *what was said* — every consumer that treats `text` as speech would quietly lie, the embedder would embed «👍» as an utterance, and "a reaction is not a tap" would rest on emoji text failing a verb table. As a type of its own, consumers opt in by name — extraction's window filters on `event_type` deliberately — and the matcher never sees a reaction at all, making **never-a-tap structural**, the same defence class as ADR-0033's exclusion. ADR-0034's transport rule is honoured, not dodged: the seam still refuses what it does not speak, so the deploy is ordered — **the runtime speaks `'reaction'` before the plane emits one** (the runtime's tests have used a `'reaction'` row as the canonical poison since slice 3; a premature plane deploy makes that row real and permanent).

**The seam records deliveries; nothing folds state in the plane.** A set, a change (👍→❤️ is a fresh event carrying the same target key), and a removal (empty text) each write their own row, append-only. Whoever needs "the current reaction" folds per (sender, target) by `SenderTimestampMS` at read time. The plane judges nothing, as ever — and a retraction stays visible *as a retraction*, which is itself a signal.

**Admissible as `agreement` evidence, with determinism binding the evidence and the target — never the intent** (ADR-0003 as amended). The model cites the reaction row's id like any message id; deterministic code reads the row back, takes the target pointer **off the row, never from the model**, and composes reaction + target as the evidence the disclosure line renders — «Confirmaste con 👍: 'me mandas 20 bultos?'» is wrong on its face or right on its face, which is where ADR-0038 wants the rep's eyes. Whether agreement *stands* — a later retraction included — is the model's judgement from the transcript, not an aperture rule: the extraction transcript renders **every reaction event as its own chronological line**, never folded, and when the target sits outside the day's window the renderer inlines its text by the same deterministic read-back — a bare unresolvable id would re-amputate the signal for exactly the common case, agreement arriving after deliberation.

**In the twin thread, a reaction gets no special treatment.** A rep's 👍 on a Borrador routes as ordinary rep input — the same path as any non-keyword reply to a proposal or question. The model reads its intent and composes whatever it says next itself («una reacción no envía — cítalo con „va“» is the twin talking, never recorded microcopy), and it cannot send regardless: the gate is on the tool (ADR-0037), and the two non-model tap minters (ADR-0006) stand untouched.

**In customer chats: context yes, trigger no.** A reaction joins the bundle and the drafting context — a thread whose decisive beat was a 👍 must stop reading as an unanswered question — but never by itself opens a turn or triggers a draft. Most reactions close a beat rather than open one, and dismissal is terminal, so noise is not free. The 👎-only reply is real and is caught where it belongs: the transcript, the daily disclosure, and rep-initiated drafting. Loosening later is cheap; un-training reps from noisy drafts is not.

**Backfill walks both history shapes.** History sync carries reactions as standalone reaction messages in the stream and as `Reactions` accumulated on the target `WebMessageInfo`; whatsmeow merges neither and dedups nothing. Both normalize to the same typed event, `backfill:true`, deduped by the seam's `(source, external_event_id)` — standalone reactions carry their own stanza id and collapse against live capture for free; the attached shape may not, so its synthetic-id recipe (and what its `Key` actually identifies) is the implementing ticket's to verify against real history blobs. Backfilled reactions feed retrieval and drafting context only, like all backfill — extraction skips the marker as it always has.

Chosen because the most common way a rep says yes on WhatsApp was invisible by construction, and the miss sat outside every measurement — the corpus holds only what was captured, so the recall number looked fine while a whole class of agreement went unfiled. ADR-0038 recorded that blindness as a bias to remember. This repeals the blindness and keeps the bias: under-filing remains the safe direction — it just stops being systematic for the one gesture whose entire meaning is yes.
