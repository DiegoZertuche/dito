# Opaque deliveries are seam rows; fail-stop is for infrastructure, never for content

**Every in-scope delivery leaves exactly one seam row, and a row the plane could not read says so.** Before this decision the plane had no such rule and behaved three different ways. A shape the seam had no slot for — a photo, a voice note, a poll, an edit, a revoke, a sticker — wrote a `'message'` row with empty text, the same husk ADR-0041 retired for reactions, which the twin read as someone saying nothing and the embedder stored as an utterance. A message the rail could not decrypt fell out of the type switch and vanished: no row, no log, no counter. A malformed instance of a known kind was stamped as written — a reaction with no target key became a gesture at nothing, and a message with no stanza id took the id `<chat>:` so the next one like it was swallowed by the dedupe. None of this was refusal and none of it was capture. The argument that decides it is ADR-0041's own: the corpus holds only what was captured, so a delivery that leaves no row — or a row that lies — sits outside every measurement anyone will ever run. A log line is outside the corpus; a row is in it.

**The third kind is `event_type: 'opaque'`; the payload stays `v:1`** and carries the common envelope (chat, sender, direction, message id, push-name where present, backfill marker, sender timestamp) plus two fields: the rail's own **kind** (`imageMessage`, `audioMessage`, `protocolMessage/REVOKE`, `undecryptable`, `reaction`, …) and a **reason** — `no_slot`, `undecryptable`, or `malformed` with the missing field named. **No raw envelope rides inside it.** For media the raw proto holds the media key, the CDN URL and a thumbnail, which is media capture through the back door for a chunk the horizon deliberately has not built; for an undecryptable message there is no plaintext to hold; for a malformed shape, kind and reason *are* the forensic value. What an opaque row gives a later promotion is not its bytes but its **counter** — how many photos, in which chats, before anything is built — which is exactly the signal "promote when it bites" needs.

**One rule, and per-shape decisions are promotions, never exceptions.** A *delivery* is any `*events.Message` regardless of content kind, any `UndecryptableMessage`, and any history entry that carries a message. Stubs (call logs, group changes, encryption notices), receipts, presence and typing are metadata, not deliveries: ADR-0023 routes them to the scoping UI, and they stay outside the seam. Every delivery the guard admits is written as `'message'`, `'reaction'`, or `'opaque'` — nothing else, and nothing is stamped under a kind it does not fit. The only per-shape act is **promotion**: lifting a kind out of `'opaque'` into a typed event of its own, exactly as ADR-0041 did for reactions and with the same deploy order. Photos, voice notes, edits and revokes are the expected next promotions. Opaque rows written before a promotion stay opaque forever under append-only; the promotion re-captures from history on relink, as reactions did.

**Guard first. The guard-undecidable case is the single permitted drop, and it is logged.** An opaque row is still an in-scope row, so scope is decided before kind, and ADR-0023 outranks this rule: content the guard cannot place — a history entry whose chat identity does not parse — never rests anywhere. That one case writes nothing and emits a log line naming the feed and the kind, never the content; it joins the ingest package's one existing diagnostic line (the history-reactions report, Dito-Core/dito#119) and is confined to the case the seam structurally cannot hold. The three feeds ADR-0023 names — live capture, history backfill, the executor's own-send write-back — apply the identical per-entry decision. Backfill stops aborting the rest of a conversation on a bad entry; it writes the opaque row and continues.

**Fail-stop is for the plane being unable to do its job, never for what it was handed.** `OnError` halts the binary, and until now that behaviour lived only in code. Every class that reaches it is infrastructure: session identity unavailable, the guard's allowlist unreadable, encrypt or marshal or insert failed. That is right — a plane that cannot capture what it is told to capture must not keep consuming — and it is now the rule. Content never reaches it. A content-shaped fatal is a wedge any counterparty could trigger by sending one malformed message, and the ticket that surfaced this (#100) had already named it so.

**Identity at the seam keeps recording deliveries and folds nothing.** Readable kinds compose `<chat>:<stanza-id>` and collapse against each other as before. An opaque row composes `<chat>:<stanza-id>:opaque`, so an opaque delivery never blocks the readable one — an undecryptable message that the sender re-delivers after whatsmeow's retry receipt, or a photo re-captured typed after promotion, writes its own row. A delivery with no stanza id composes `<chat>:opaque:<hash of the envelope bytes>`, hashed at write time and not stored, so a redelivery of the same bytes still collapses. Which row *stands* is the consumer's fold, where ADR-0041 put "the current reaction".

**The runtime speaks `'opaque'` before any plane emits one — and that order is a rule of the seam, not of one kind.** ADR-0041 stated it for reactions; it holds for every kind that will ever be added, because the consumer refuses an `event_type` it does not know and a refused row is pending forever. Speaking the kind means: a **placeholder beat** rendered by code from the kind — «[foto]», «[nota de voz]», «[mensaje que no se pudo leer]» — one chronological line in every context that reads the conversation window — the extraction transcript, drafting context, and Q&A when it reads a chat — never text and **never embedded**, which ends the husk's pollution of the vector store. The two halves of that sentence are one decision, not two: a row that is not embedded cannot be found by similarity retrieval, so a placeholder surfaces wherever the conversation is *read* and nowhere it is *searched* (the build, Dito-Core/dito#124, confirmed the conflict and this is the ruling). In a customer chat, **context yes, trigger no**: a draft about content the twin cannot see is noise, and dismissal is terminal. In the twin thread, **ordinary rep input**: the twin says in its own words that it cannot read photos yet, composed, never microcopy (ADR-0037). The **fold**: a readable row supersedes an opaque row for the same message, per (chat, stanza); and an opaque row supersedes the legacy empty-text `'message'` husk for the same message — without that inversion, relink backfill would write honest opaque rows beside the old husks and the husk would win, so existing twin memory would never heal. An opaque row is **citable like any row, with no hard gate**: the deterministic read-back composes the placeholder as the evidence text and the disclosure line shows it on its face, which is where ADR-0038 wants the rep's eyes; the transcript makes the opacity explicit and the model weighs it.

**What this does not settle.** A row the consumer refuses still sits pending forever with every later event for that twin behind it, and nothing detects it — NFR-1's paging never fires because the rail is up. That is always-on hardening and is recorded as an obligation on Slice 7 (Dito-Core/dito#115); the deploy-order rule above is the day-to-day discipline, not a detector.

Chosen because the plane's honesty is measured only through the corpus, and every shape the plane could not carry was either lying in it or missing from it — while the one remedy the code offered, halting the binary, would have handed every counterparty a switch for the rep's twin.

**Amendment 2026-09-09 (the self-chat; the rule reaches the runtime).** Two rulings from the slice-6a boundary (([#225](https://github.com/Dito-Core/dito/issues/225)), F13 and F1; built as [#240](https://github.com/Dito-Core/dito/issues/240)). The rule above says an opaque delivery is recorded; it did not say what the twin does with one in the **rep's own self-chat**, and the runtime treated each as a fresh rep message it could not read — ran a thread execution and posted «tu mensaje me llegó ilegible, ¿me lo reenvías?» into the self-chat and onto the dashboard. Every pairing burst and every on-demand history page ([ADR-0023](0023-capture-governance-at-the-socket.md) as amended) delivers protocol messages into that chat, so link day opened on twenty-six apologies. **An opaque delivery in the self-chat is recorded in twin memory as any opaque row is, and never answered**: no execution, no post, no send — the pairing-burst shape, the history-page shape and a live opaque delivery alike. Whether a rep-authored message that arrives opaque ever earns one «reenvíamelo» is a question for the thread on the dashboard ([#215](https://github.com/Dito-Core/dito/issues/215)), not a promotion this rule makes. And the sentence *fail-stop is for the plane being unable to do its job, never for what it was handed* now binds the runtime by the same words: an execution that fails on its input is content, recorded and left behind; the seam, the bundle and the key are infrastructure ([ADR-0010](0010-single-writer-lease.md) as amended).
